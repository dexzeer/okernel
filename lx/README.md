# Linux and Windows programs on okernel

Moved from AGENTS.md to keep that file short.

**Linux subsystem** (`src/lx*.c`, `boot/lm.asm`; shell `lx <path> args`): x86-64 Linux ELF programs (static, PIE, dynamic via PT_INTERP) run natively in ring 3. `lx_enter` irets into the task (`lx_running` tells `lm_enter` that ring 3 belongs to one); SYSCALL/interrupts/faults store the registers in the task's `struct lx_regs` (TSS.rsp0 points at its end) and "return" from `lx_enter` into the main loop (`lx_poll`), IRQs are served first as if the loop was interrupted at `lx_irq_resume`. A slice ends with `fpu_save` + `fpu_reset`: the task's MXCSR must not follow the kernel's SSE code. User memory = VMAs + demand paging below `LX_USER_TOP`; the kernel reads/writes user memory by physical walks (`lx_copy_in/out`), never through CR3. Blocking calls rewind `rip` by 2 and re-run when `block_fn` says so (`block_complete` for calls that already returned). Threads share `lx_mm/lx_files/lx_sighand` (clone), futex in `lx_sys.c`, signals with rt_sigframe in `lx_sig.c`, UNIX/inet sockets `lx_net.c`, epoll/eventfd/timerfd `lx_ev.c`, tty `lx_tty.c`, `/dev/fb0` + `/dev/input/event0` (a desktop window) `lx_fb.c`, file system `lxfs.c` (memory tree, root filled from the GRUB `module` tar). Not done: TCP servers, 32-bit Linux binaries. **X11:** `lx/xsrv/` is `xokai`, a freestanding X server (core protocol, little-endian clients, TrueColor depth 24 visual, no extensions; run `lx /bin/xokai &`, clients connect to `/tmp/.X11-unix/X0`; it calls `setsid` (syscall 112 = the task leaves its terminal) so the shell prompt comes back). There is no X window manager: every top-level X window (child of the root) becomes a `/dev/okwin` window created at its first map (`override_redirect` = `OKW_F_NOFRAME` popup), WM_NAME/_NET_WM_NAME become the title, WM_DELETE_WINDOW is sent on `OKE_CLOSE`; child windows are composited by the server into the top level's buffer (clip = window rect minus later siblings minus children, `win_visible`), Expose events come from `win_expose_tree/win_expose_rect`. Fonts are fixed-cell bitmap-like fonts (`fixed`, `6x13`, XLFD names) rasterised glyph by glyph with `OKW_TEXT`; selections bridge to `OKW_CLIPBOARD` only when nobody owns them. Drawing: raster functions, plane mask, tiles/stipples, dashes, wide lines, polygons, arcs, CopyArea/CopyPlane, PutImage/GetImage, all software in `gfx.c`. Not done: passive grabs, XKB/RENDER/SHM/BIG-REQUESTS/XInput, ConfigureNotify when the desktop moves a window. **Shipping:** `tools/lx/build_root.sh` builds the product root (own programs of `lx/src`, `xokai`, our DLLs and the Windows demo exes; no host code), `make desktop`/`make disk` put it in as a GRUB `module` (`build-host/lxsys.tar`; the disk has it on p1 and, for the known-good entry, on p2); `build_tests.sh` reuses it and adds glibc/host test inputs. Test: `test_lx_image.py`. Tests: `test_lx_x11.py` (own raw-protocol client `lx/xsrv/clients/xtest.c`), `test_lx_xlib.py` (a real libX11 program `lx/test/x_xlib.c`, needs `HOSTBINS=1`). **Windows x64 programs (PE32+)** run in the same tasks: `lx_pe.c` maps the image and the DLLs it imports (search `/windows/system32`, `/windows`, `/bin`; names are case-insensitive; `api-ms-*`, kernelbase, ntdll, advapi32 resolve to our `kernel32.dll`, ucrtbase/msvcr*/api-ms-win-crt to our `msvcrt.dll`), relocates, binds imports (an unresolved one points at `0xAE000000+16*i`: a fault there names it), builds PEB/TEB/TLS in the meta region `0xAF000000` and starts through a generated stub (DllMain of every DLL, then the entry). GS base = TEB (`arch_prctl 0x1001`). Our own DLLs in `lx/win/` (kernel32 incl. the ntdll bits, msvcrt: all written from scratch, C compiled with `gcc -mabi=ms`, user mode, they use Linux system calls; services 0x1000-0x1002 = LoadLibrary/GetProcAddress/GetModuleHandle). Toolchain: `tools/pe/pebuild.sh` (gcc -> `ld -T pe.ld` -> `mkpe.py` ELF-to-PE converter, import stubs generated from `imports.txt`, exports from the `EXPORT` lines), `lx/win/build.sh` builds everything into `build-host/winroot`; `tools/pe/dump.py` lists a PE's imports. Windows rule: functions are entered with rsp = 8 mod 16 (the start stub keeps rsp 16-aligned before each call). **SEH** (`lx/win/kernel32/seh.c`, all user mode): a fault of a Windows task is not a signal: the kernel (`win_exception` in lx.c) copies the registers to the user stack and continues at `KiFaultEntry` (registered by kernel32's DllMain with arch_prctl 0x1005), which builds CONTEXT + EXCEPTION_RECORD and walks the stack with `.pdata`/`.xdata` (`RtlLookupFunctionEntry`/`RtlVirtualUnwind`, module of an address = service 0x1003), calling language handlers (`__C_specific_handler` = scope tables of __try/__except/__finally; `RtlUnwindEx` runs the termination handlers and lands in the __except block). Our own code gets unwind tables from gcc's CFI (`tools/pe/unwind.py`, run by mkpe; needs `-fasynchronous-unwind-tables -fno-shrink-wrap`, `ld -q`; `MKPE_UNWIND_VERBOSE=1` lists functions it could not describe: frame pointer / DRAP functions and noreturn ones). gcc has no `__try`, so tests write guarded regions in assembler with hand made UNWIND_INFO in `.sehdata`/`.sehfunc` (32-bit relocations there become RVAs). Not done: C++ exceptions (`__CxxFrameHandler3/4`, `_CxxThrowException`), epilogue emulation in RtlVirtualUnwind, stack overflow detection. Test: `lx/win/tests/seh` via `test_lx.py`. **GUI:** `/dev/okwin` (`src/lx_okwin.c/.h`, protocol shared with user space) is the native window device: `OKW_CREATE/MAP` give a window with a shared BGRX buffer, `OKW_PRESENT` publishes a rectangle, events (mouse, wheel, Linux key code, char, focus, close, resize) are `read()`, `OKW_TEXT` rasterises UTF-8 with the kernel's Noto engine into a coverage mask, `OKW_QUERY` = window position and pointer. Our `gdi32.dll` (`lx/win/gdi32`: DCs over pixel surfaces, pens/brushes/bitmaps/DIBs, shapes, BitBlt, text via OKW_TEXT; private `__gdi_*` exports for user32) and `user32.dll` (`lx/win/user32`: classes, window tree with child windows drawn into the top level's buffer, one message queue, WM_PAINT/timers/input translation, DefWindowProc, MessageBox, built-in BUTTON/STATIC/EDIT/LISTBOX, wsprintf) run on it; menus (bar, popups, submenus, mnemonics, `menu.c`; popups are frameless okwin windows, `OKW_F_NOFRAME`), accelerators, dialogs (`dlg.c`: both template formats, DialogBox/CreateDialog, IsDialogMessage), resources (`res.c`: bitmaps/icons/cursors from PE resources or files, LoadString in draw.c, FindResource/.mui in kernel32 `rsrc.c`), the clipboard (`clip.c`, text shared through `OKW_CLIPBOARD`), COMBOBOX (`combo.c`), SCROLLBAR controls and the scroll bars of windows (`sbar.c`: 17 px margins, client area reduced) are real. NOT done: common controls (comctl32: list/tree view, toolbar, status bar...), comdlg32, shell32, registry, winmm, ws2_32, C++ exceptions. Resources for our own test programs: a `rsrc.txt` in the program's directory (`tools/pe/rsrc.py` spec: BITMAP/ICON/MENU/DIALOG/ACCELERATOR/RCDATA/STRINGS) becomes the .rsrc section, `gen.py` there makes the binary templates. Build traps: `pebuild.sh` has `-Werror=implicit-function-declaration` (a pointer-returning function used undeclared is truncated to int: that was a real crash); `KEEP_ELF=1` keeps the linked ELF next to the dll for `nm`; the unhandled-exception message prints a call trace. Key presses and releases reach okwin through an IRQ queue (`keyboard_next_transition`), and a window created with `OKW_F_HIDDEN` is shown (with the opening animation) by `OKW_SHOW 1`. Bases: kernel32 0x6C000000, msvcrt 0x6D000000, user32 0x6E000000, gdi32 0x6F000000. A test exe with a `gui` marker file in its directory is built as GUI subsystem. Real Microsoft console binaries run (findstr.exe, sort.exe from the host's System32; test `test_lx_msbin.py`, the files are not in the repo): `lx/win/kernel32/rsrc.c` has FindResource/LoadResource on the mapped image with the fallback to `<dir>/en-US/<name>.mui` (RT_MESSAGETABLE for FormatMessage, RT_STRING for LoadString); our `FILE` is 48 bytes because compiled programs index `__iob_func()` with the MS stride. Shell `lx trace on|off` prints every Linux system call with its path argument (`[lxt]` serial lines): the first tool when a foreign binary prints nothing. Test programs: `lx/win/tests/*` (hello.exe, crtdemo.exe, guidemo.exe); GUI test `tests/headless/test_lx_win32gui.py`, device test `test_lx_okwin.py`. Trap: Python `open(p).write()` on Windows turns LF into CRLF (breaks `sh` scripts); use `newline=''`. Tests: `HOSTBINS=1 sh tools/lx/build_tests.sh` builds `build-host/lxtest.iso` (programs of `lx/src` without libc + glibc tests of `lx/test` + host bash/ls), then `tests/headless/test_lx.py`, `test_lx_gui.py`. Trap: the Bash tool collapses `\\` in commands, so write perl/C that contains backslashes with the Write tool.

## The terminal

Programs in a terminal window write through an xterm-style parser in `src/lx_tty.c` (TERM=xterm: cursor movement, erase, insert and delete, scroll regions, SGR colours including 256 and RGB, the alternate screen, DECCKM). The cursor is the window's own, so the shell carries on where a program stopped; `lx_tty_release` resets the terminal when the window's last program exits. The cell font is single-byte: UTF-8 is decoded, line drawing becomes ASCII, anything else `?`. Keys without a character come through `keyboard_set_ext_callback`; arrows, Home/End, PgUp/PgDn, Insert/Delete and Esc reach a program only when it reads raw, other windows keep the old scroll codes. OSC 7777 prints the cell grid on serial for tests. Test: `tests/headless/test_lx_term.py` (`lx/src/vtcheck.c`, plus real nano, vim and curl from `tools/lx/real_progs.sh`).

## DOSBox

Ubuntu's prebuilt DOSBox 0.74 (SDL 1.2 compat on SDL2 on Xlib, dynamic CPU core) runs against `xokai`: `tools/lx/dosbox_root.sh` adds it to a test root, `tests/headless/test_lx_dosbox.py` runs it. It needs more than the default 512 MB of guest memory (`OKVM_MEM=2048`). Silent: there is no Linux sound device yet. Frame rate and a real graphics program are not measured yet.
