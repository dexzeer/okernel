# KAnarchy OS — Handoff

**KAnarchy OS** is a from-scratch OS in C and x86 assembly (no libc, no Linux, no third-party code except fonts). The kernel is **okernel** (also the repo folder), the desktop is **Okapi**, the browser is **okai**. It runs in QEMU (WHPX/KVM), with an optional real-laptop build. Refreshed 2026-11-01.

Read order: this file (orientation), `AGENTS.md` (the living rulebook: one bullet per finding, the traps are there), `LAPTOP.md` (real-laptop image), `tests/headless/TESTING.md` (test harness).

## Working agreements (the owner's, keep them)

- **From scratch only.** No third-party code of any license. User-approved exceptions: fonts, Realtek's `rtw8821c_fw.bin` (runs on the chip), the AAC Huffman tables read out of FAAD2, CELT written from the RFC 6716 reference source.
- **QEMU first.** The real-laptop port is optional and later. Never suggest flashing the stick. Never write power/clock MSRs without the full voltage-id path (a bare PERF_CTL write froze the laptop).
- **Test at normal speed** (WHPX/KVM), not throttled to the laptop.
- **Honest identity.** No Chrome/Firefox claim, no client hints, no faked attestation. Consent dialogs are the user's to click.
- **Done means** built, tested, working in QEMU, and not blowing kernel memory.

## Rules that bite (details and the story behind each: AGENTS.md)

1. Paging before the framebuffer (identity-mapped, above 4 MB); the boot PD maps phys 0-64M with 4 MB pages and the image must fit.
2. **The cursor lives on the framebuffer**, moved in the mouse IRQ. Never draw it into the backbuffer or recomposite for mouse motion. Direct backbuffer writes must call `graphics_mark_dirty`/`graphics_mark_rect`.
3. Never a bare `sti` in code reachable from an IRQ (keystrokes came out reversed). Keys are queued by IRQ1 and dispatched from the main loop; shell, navigation and page JS never run in an interrupt.
4. The main loop halts when idle; packets are polled. Anything per-iteration that touches MMIO starves the PIT.
5. XMM only in `simd.c`/`vp9_simd.c`; handlers never touch it. ISR stubs `cld` first. `memcpy` is `rep movs`.
6. New `struct process` fields go at the tail; use `offsetof`. `sched_yield` on the trap stack never switches CR3/ESP0. Syscall pointers go through `paging_user_range_valid`.
7. `-fno-pic -fno-pie -mno-red-zone`; `section .note.GNU-stack` last in `.asm`. Big tables on the heap, not BSS.
8. Web engine: integer/fixed-point (LU = 1/64 px), no libgcc (`w_div64`/`w_muldiv`), every engine call through `run_job()` (own 1 MB stack). ojs: doubles at 53-bit x87 precision, never cast double to int in hot paths (`d2i64`/`dtoi32`), values held in C memory must be GC roots.
9. TCP: the advertised window is the ring's free space; fast retransmit counts only pure-ACK repeats. e1000 RX: `RDT` = last processed index.
10. TLS: HKDF labels need `"tls13 "`; transcript hash is over handshake messages, not records; nonce = IV xor sequence; plaintext ends with the content type then zeros; offer only x25519 in `key_share`.
11. Hardware that QEMU cannot show (laptop touchpad, USB quirks, power MSRs) gets a log path (`devlog`, stick log), not blind writes.
12. Tooling: Python patch scripts mangle `\n` inside C string literals (use Edit); if WSL shows files as mode 000, `find . -path ./.git -prune -o -type f -perm 000 -print0 | xargs -0 chmod 755`.

## YouTube and the attestation wall

Watch pages load, search works, video plays smoothly (30 fps steady with `-smp 4`, A/V in sync, streaming fetch, MSE ad hand-over fixed, Range-streamed long videos). TCP window scaling (RFC 7323, shift 2 = the 256 KB receive ring) let YouTube's bandwidth estimate rise: the player now climbs 240p -> 360p -> 480p in the first seconds (it stayed on 240p with the 64 KB window). The player picks resolution from its own estimate and the player size; we do not force formats. After ~25-50 s the video servers answer 107/123-byte refusals and `youtubei/v1/player` returns a 549-byte error: BotGuard's token is not accepted. Signing in does not change it (sign-in itself works since URLs are 8 KB and cookies uncapped).

Measured, not solved (AGENTS "Why is YouTube's BotGuard token rejected"): BotGuard runs to completion here and produces a snapshot the same size as Edge's, but it computes its signals inside its own VM, so API traces cannot show what it dislikes. Fixed on the way: wire User-Agent now equals `navigator.userAgent`, `Accept-Language`, `Referer`, Fetch Metadata, Origin on unsafe methods, WebIDL shapes. Remaining differences from Edge: no Trusted Types, no `Intl`, no WebGL/Web Audio, a stub `about:blank` iframe window, the JS engine itself (not V8). Policy: no spoofing, no Chrome identity.

Re-measured 2026-10-28 ("take down the attestation wall"), two rounds. **Round 1 — Mullvad VPN on:** every client (WEB/IOS/ANDROID/TVHTML5/ANDROID_VR probes, plus a real headless Edge with a Chrome UA, cookies and consent accepted) got `LOGIN_REQUIRED "Sign in to confirm you're not a bot"`, and the watch-page HTML served no formats — only itag-18 decoy URLs with bogus timestamps that 403. Nothing engine-side can act while the IP is flagged; datacenter IPs (Mullvad) are a non-starter. Also learned: the `youtubei/v1/player` 400 FAILED_PRECONDITION at page load is a BotGuard **probe**, not a failed request — the page (`lV$` in kevlar_base) builds `new Request("data:application/json;base64,...")`, redefines the `url`/`method`/`body` getters onto the real endpoint and POSTs an empty body, expecting exactly that 400.

**Round 2 — VPN off (residential IP):** the HTML serves real formats and playback starts — then after ~30-50 s every SABR refresh answers a 123/143/145-byte UMP (ATTESTATION_REQUIRED) and playback starves when the ~20-60 s buffer drains. **A fresh headless Edge does exactly the same** (currentTime sampling: plays to t=33 s, at ~56 s the player tears the video down, dead to the end of a 130 s run), and a **headed** fresh Edge dies the same way — cookie-less sessions are demoted regardless of engine. The SABR requests of both sides carry the same structure: the poToken in field 19.2 (okai 81 bytes, Edge 90 — constant per session on both sides), a DER ECDSA signature in 5.2, visitor data in 332.

**The GenerateIT "snapshot" is BotGuard's error-report collection**: when the collection aborts the request body is readable — `["<challenge id>", "E:<message>:<TypeError text + stack>"]`, the VM deliberately triggers errors and records message + stack. That made the remaining signal surface visible and fixable: Trusted Types were completed to match a probed Edge (`isHTML`/`isScript`/`isScriptURL` exist, duplicate `createPolicy('ad')` names are allowed — the spec's duplicate-throw would have broken BotGuard's 4x creation), nine error-message patterns were made V8-exact (value-bearing "5 is not a function", "(intermediate value).x", JSON's current "Expected property name or '}' in JSON at position N (line L column C)" family with the ±10-char `..."1,1,x]"...` snippet, "Invalid regular expression: /(/: Unterminated group", "Invalid flags supplied to RegExp constructor 'gg'", "Invalid array buffer length", the two iterable forms with the built-in long form "number 1 is not iterable (cannot read property Symbol(Symbol.iterator))", per-operation revoked-proxy texts, "Assignment to constant variable.", "Cannot use 'in' operator to search for 'a' in 1"; `tests/web/js/errmsg.js` + `build-host/bginv/msgspec.js` are the batteries), and eval-frame stacks now carry the V8 origin chain ("at eval (eval at <anonymous> (site), <anonymous>:L:C)") via the compiled filename (`ojs_frame_site` in b_error.c, run_eval in b_global.c). `OJS_TRACE_MISS` (failed property lookups, host builds only) was recovered from the a56957e work. Probe tools: `tools/yt/client_probe.mjs`, `tools/yt/session_probe.mjs <videoId> [ua]`, `tools/yt/bgprogram.mjs`, `tools/yt/bgrun.sh`, `tools/yt/genit_probe.mjs`, `tools/ui/edge_yt_cdp.mjs`, `tools/ui/edge_yt_long.mjs`, shell `fetchdump` (19.2 = the poToken), `build-host/bginv/ump.py|sabrcmp.py|tokcmp.py|snapcmp.py|gel.py|snapdiff.py` decode the dumps.

**The differential rig (2026-10-28, late)**: the BotGuard VM now runs OUTSIDE the browser — same shim + same challenge program + same VM script under Node (real V8) and under `ojs_run`, built by `tools/yt/bgrun.sh` (program + content binding extracted by `tools/yt/bgprogram.mjs` from the HTML's `\x22bgChallenge\x22` blob; shim in `build-host/bginv/bgshim.js`, driver in `bgdriver.js`; invocation: `trayride.a(program, setup, true, undefined, telemetry, [[],[]], undefined, false, loggers)[0]` is a sync snapshot function taking `(callback, [contentBinding, signedTimestamp, webPoSignalOutput, skipPrivacyBuffer])`). Both engines produce full encrypted snapshots: **V8 2100 bytes vs ojs 2106 — the engine differs by 6 bytes**; the whole host-API call trace matches structurally. The API-surface hypothesis died by measurement: adding AudioContext/WebGL/Intl/userAgentData/serviceWorker/etc. to the shim left the snapshot at exactly 2801 chars. The integrity-token length is program-generation-dependent, not a score: the rig's V8 snapshot posted to GenerateIT (needs the page cookies AND its own `X-Goog-Api-Key: AIzaSyDyT5W0Jh49F30Pqqtyfdf7pDLFKLJoAnw` — bare posts get 403 "unregistered caller") returns a 108-char token where our kernel's page flow gets 107 and Edge got 88 on a different `js/th` hash. The 3 h visitor-maturation run was killed as a wall-shot (a session that fails attestation for hours builds a negative record, if it builds anything). Verdict so far: **every layer we can observe — protocol, snapshot, mint, token grade — matches a real browser within noise; fresh headed Edge is demoted at the same ~40 s mark; the surviving hypothesis is Google's server-side visitor/account trust tier, which a fresh or failing session cannot build**. The rig stays: any future "why is the token refused" question is now a diff, not a guess.

## Known limits

TLS 1.3 only (no TLS 1.2, no SHA-384 suites). HTTP/2 without push; no congestion control. No WebGL, Web Audio, WebRTC, EME, ServiceWorker, XPath, multipart uploads. CSS transforms cover translate*/scale* (with `transform-origin`) but not rotate/skew/3d. CJK glyphs beyond the bitmap table are tofu (line breaking is done). WOFF2 fonts unsupported. Wasm: no SIMD/threads/exceptions. SILK/hybrid Opus and AAC SBR missing. Page JS is slow under TCG (use WHPX/KVM). Single scheduler CPU. In-memory VFS: only PFS-synced files survive reboot.

## Bug classes worth remembering

Stale objects after a header change (keep `-MMD -MP`); 16-bit offsets in big arenas; stale buffers leaking into the next request; DNS/fetch owner races (now a request table); polled hardware starved by a spinning loop; interrupts re-enabled inside handlers; DF set when an interrupt lands in a backward `memmove`; PS/2 init reading config bytes without waiting; clicks routed by slot instead of z-order; cached chrome re-rendered under a small clip; quadratic parser/const-table code on huge bundles; 16-bit const indices; URL/cookie buffers that silently truncate.
