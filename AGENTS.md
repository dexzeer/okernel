# AGENTS.md — KAnarchy OS (okernel kernel)

From-scratch OS in C + x86 assembly. Kernel = okernel, desktop = **Okapi**, browser = **okai** (orientation: HANDOFF.md). Two targets: text mode (VGA text) and desktop mode (GRUB framebuffer, 1920x1080 requested). Runs in QEMU and on a real laptop. No standard library, no Linux, no BIOS calls in protected mode.

This file was condensed on 2026-10-18. The long per-feature history it used to carry (measurements, bug hunts, exact numbers) is in git: `git show b02375e:AGENTS.md`. Keep this file to rules, traps and pointers; put narrative in HANDOFF.md or commit messages.

## Build and run

```bash
make desktop       # kanarchy-desktop.iso (primary)
make text          # kanarchy-text.iso
make clean         # nukes .o, .bin, .iso, isodir/
```
Needs `gcc` (multilib), `nasm`, `ld`, `grub-mkrescue`, `xorriso`, `mtools`. Other images: `make disk` (installed disk with the recovery system), `make laptop` (BIOS+UEFI), `kanarchy-res.iso VID_W= VID_H=`, `kanarchy-x2apic.iso`, `kanarchy-i915test.iso`.

```bash
qemu-system-i386 -accel kvm -accel tcg -m 512 -cdrom kanarchy-desktop.iso -boot d -vga std -device e1000,netdev=net0 -netdev user,id=net0
```
Use hardware acceleration (TCG is ~10x slower). Windows: `run-windows.bat` (x86_64 QEMU, WHPX, `-smp 4`, 1536 MB, AC'97 audio; the i386 QEMU build has no WHPX). Serial debug: add `-nographic -serial stdio` — serial is ground truth for network bugs.

## Kernel gotchas

- **Paging/boot.** Desktop links high-half at 0xC0100000 (`linker-high.ld`; text keeps `linker.ld`). LOW trampoline `_start` (e_entry 0x100030) + private boot GDT → `_start_high` → `kernel_main`. Boot PD maps phys 0-64M with 4 MB PSE pages; image + .bss is ~11 MB (a 4M map triple-faults before serial init). Order: memory → mboot copy → `paging_init` → process → graphics (identity FB). Framebuffer is above 4 MB: never touch it before paging. Big tables go on the heap, not BSS. `V2P`/`P2V_U32` in `src/memlayout.h`. The usable kernel address space is ~735 MB; more RAM does not help.
- **Compiler flags:** `-fno-pic -fno-pie -mno-red-zone` required. Only `src/simd.c`, `src/media/vp9_simd.c`, `src/media/vcvt.c` are built `-msse2` and only they may use XMM; everything else `-mno-sse` (x87 for ojs). Interrupt handlers must never touch XMM (not saved there). `section .note.GNU-stack` must be the LAST section in .asm files.
- **Makefile uses `-MMD -MP`:** never drop it (a stale header once left a struct at the old size and made every HTTPS fetch fail). When in doubt `make clean`.
- **Interrupts:** never a bare `sti` in code reachable from an IRQ (save/restore IF; `rng_cli/rng_sti`, `irq_save`). ISR/IRQ stubs `cld` before calling C (an IRQ inside memmove's `std` region otherwise ran string ops backwards). Keystrokes are only queued by the IRQ (`key_q`); `keys_dispatch()` in the main loop runs them with their own modifier state. Page JS (ojs is not reentrant), navigation and shell commands never run from an IRQ.
- **Main loop:** halts when idle (`okai_wants_cpu`: 1 CPU work, 2 requests in flight, 3 timed wait, 0 nothing → LAPIC one-shot or `hlt`). The halt is `cli; check key queue; sti; hlt`. `[fps] N loops=M busy=P%` is the 1 Hz perf line. During long page scripts the ojs hook calls `engine_pump` every 10 ms (media tick, network, input; it never draws or calls into the page).
- **Cursor** is NOT in the backbuffer: alpha-blended onto the framebuffer in the mouse IRQ (`src/cursor.c`). Never draw a cursor into the backbuffer. PS/2 init reads every controller reply in order with a wait; the IntelliMouse wheel handshake (200/100/80 + 0xF2, wait for ACK then ID) must keep its ordering.
- **Graphics:** backbuffer + dirty spans (`mark_span`); code writing `graphics_get_buffer()` must call `graphics_mark_dirty/graphics_mark_rect`. Shell `gfxcheck` verifies framebuffer == backbuffer. Framebuffer is write-combining (PAT entry 1). Screen size comes from the bootloader (`gfx_w/gfx_h`; static tables sized for 1920x1080 or 4096x2304). Display backends: GRUB framebuffer (fallback), virtio-gpu (`-vga virtio`, backbuffer is the resource backing; polled), i915 = read-only probe only (shell `gpu`).
- **Scheduler:** preemptive via `process_switch_to`/`context_switch`; never switches from ring-3 trap stacks. `sched_yield()` on the INT 0x80 stack only resets the slice. `process_switch` (CR3+ESP0) is handoff-point-only. New `struct process` fields go at the TAIL; use `offsetof`, never index PCB words by hand.
- **Syscalls:** INT 0x80 ABI 0-18 (print, exit, write, read, open, close, fork, exec, sbrk, pipe, dup, wait, kill, mmap, munmap, panic...). Every user pointer goes through `paging_user_range_valid()` first. `enter_user_mode` takes eip→EAX, esp→EDX.
- **SMP** (`acpi.c`, `lapic.c`, `smp.c`, `boot/ap_tramp.asm`): APs only run jobs (`smp_parallel_for(fn, ctx, n, grain)`, `smp_async_start/done`); they never touch the scheduler, windows, serial or okai. Jobs may kmalloc/kfree and use x87/SSE. **Nothing called from inside an `smp_parallel_for` item on the boot CPU may take `pub_lock`** (`smp_async_start` returns -1 there; nested parallel jobs run inline) — violating this froze the kernel when a parallel GC ran during video. Tests: shell `smp test`, `tests/headless/test_smp.py`, `tests/test_acpi.c`. Hooks: `OKVM_SMP=n`.
- **Clocks:** `tick_count` follows the TSC under a hypervisor (QEMU on Windows loses 15-40% of PIT interrupts); anything counting timer INTERRUPTS (sched slice, `audio_tick`) runs at the lost rate. `pit_delay_us` was broken before 2026-10-10.
- **Memory:** segregated-fit heap and page allocator are spinlocked. The first write to a guest page costs ~19 µs under WHPX; `heap_pretouch` pre-faults in the idle path. Picture slots shrink/cap when free memory is low (`out_budget_px`, `frame_budget`).
- **memcpy/memset/memmove** are `rep movs/stos` inline asm (so GCC cannot turn them into self-calls); memmove's backward path sets and clears DF.
- **PFS/ATA:** OKPFS1 write-through (`fs_delete` copies the name before clearing; static hydrate/sync buffers, the trap stack is 4 KB). OkVM disk tests use `OkVM(tag, disk=path)`; a stale `-hda` QEMU holds the image lock. On a disk with an MBR, OKPFS1 lives in its own partition (sector numbers in `pfs.c` are partition-relative) and sector 0 is never formatted; a disk without one keeps the old whole-disk layout.
- **Installed disk + panic/recovery** (`make disk` → `kanarchy-disk.img`, layout in `src/part.h`, builder `tools/disk/mkdisk.py`, menu `tools/disk/grub.cfg`): MBR + GRUB (BIOS core in the gap, `BOOTX64.EFI`/`BOOTIA32.EFI` on p1), p1 FAT `KANBOOT` (kernel, grubenv), p2 FAT `KANRECOV` (`/known/kanarchy.bin`), p3 log (type 0xDA: the klog region of `klog.h` + crash records of `crash.h`), p4 OKPFS1 (type 0x4B). `ata_write` refuses p2 always and p1 in the desktop except the two grubenv sectors (`ata_protect`/`ata_allow`). A CPU exception or `kpanic()` ends in `panic.c`: the screen shows only the cause and a call trace (a stack *scan* resolved with the `.ksyms` table from the two-pass desktop link, `tools/ksyms.py`); registers etc. go into the crash record (+ klog flush) on p3; `next_entry=recovery` in grubenv (GRUB's one-shot), 30 s countdown, R/D/H on the polled PS/2 port. No heap, locks or IRQs there. `acpi_pm_reboot` INITs the APs first (`smp_stop_others`): QEMU WHPX with `-smp` > 1 hung on reset otherwise. The recovery desktop is the known-good kernel booted with `recovery` on the command line (`recovery_mode` in desktop.c): tinted wallpaper, no icons, a closable no-input "kernel panic" window (cause + first trace entry of the last boot's crash record; none if the last boot did not crash), `recovery#` terminal running `src/recovery.c` (crash, log, part, ls, fsck, rm, hexdump, restore, knowngood, memtest); long output opens in `textview.c` windows; OKPFS1 is not mounted and klog is not written (the crashed boot's log stays). The recovery shell only runs what its `help` lists (`recovery_mode` gate in `shell_execute`). GRUB never shows a menu (`timeout=0`; `keystatus --shift` is unreliable in QEMU and a menu waiting forever hung a test for 27 min); `ata_read/ata_write` use `rep insw/outsw` (one VM exit per sector, not per word: the pfs mount took 4 s under WHPX before). UI text is terse by owner request: no hint lines. `run-disk.bat` boots the image in Windows QEMU. Test: `tests/headless/test_recovery.py` (`OkVM(tag, boot_disk=img)`); `run /bin/panic [fault]` triggers it (syscall 18). ATA PIO only: no AHCI/NVMe/eMMC, so real machines need a legacy IDE mode for now.
- **Long mode (since 2026-10-25).** The desktop kernel runs the CPU in x86-64 long mode but is still 32-bit code: it executes in COMPATIBILITY mode (CS 0x08), every kernel address is below 4 GB, page tables are 4-level (`paging.c`: kernel half = one shared `kpd[3]`, mirrored at 0xFFFFFFFFC0000000 for 64-bit code; address spaces via `aspace_*`). `start.asm` enables PAE+LME+PG (needs an x86-64 CPU; QEMU: `qemu-system-x86_64`, okvm uses it) and the AP trampoline does the same. Interrupts: `boot/lm.asm` has 256 64-bit thunks; from 32-bit code they rebuild the old 32-bit frame and enter the legacy handler (`lm_legacy[]`, filled by `idt_set_gate`), so `isr.asm`/`idt.c` handlers are unchanged. GDT: 0x08/0x10 flat 32-bit, 0x18/0x20 user 32-bit, 0x28 user 64-bit code, 0x30/0x38 kernel 64-bit (SYSCALL), 0x40 64-bit TSS (`rsp0`). The text kernel stays 32-bit protected mode (`gdt32.c`, `idt.c` without `-DLONGMODE`). `lgdt/lidt` take 10-byte descriptors. No libgcc: no `__builtin_ctzll`, 64-bit `/` `%` via divdi3.
- **Linux subsystem** (`src/lx*.c`, `boot/lm.asm`; shell `lx <path> args`): x86-64 Linux ELF programs (static, PIE, dynamic via PT_INTERP) run natively in ring 3. `lx_enter` irets into the task; SYSCALL/interrupts/faults store the registers in the task's `struct lx_regs` (TSS.rsp0 points at its end) and "return" from `lx_enter` into the main loop (`lx_poll`), IRQs are served first as if the loop was interrupted at `lx_irq_resume`. User memory = VMAs + demand paging below 3 GB (`LX_USER_TOP`); the kernel reads/writes user memory by physical walks (`lx_copy_in/out`), never through CR3. Blocking calls rewind `rip` by 2 and re-run when `block_fn` says so (`block_complete` for calls that already returned). Threads share `lx_mm/lx_files/lx_sighand` (clone), futex in `lx_sys.c`, signals with rt_sigframe in `lx_sig.c`, UNIX/inet sockets `lx_net.c`, epoll/eventfd/timerfd `lx_ev.c`, tty `lx_tty.c`, `/dev/fb0` + `/dev/input/event0` (a desktop window) `lx_fb.c`, file system `lxfs.c` (memory tree, root filled from the GRUB `module` tar). Not done: TCP servers, 32-bit Linux binaries. **X11:** `lx/xsrv/` is `xokai`, a freestanding X server (core protocol, little-endian clients, TrueColor depth 24 visual, no extensions; run `lx /bin/xokai &`, clients connect to `/tmp/.X11-unix/X0`; it calls `setsid` (syscall 112 = the task leaves its terminal) so the shell prompt comes back). There is no X window manager: every top-level X window (child of the root) becomes a `/dev/okwin` window created at its first map (`override_redirect` = `OKW_F_NOFRAME` popup), WM_NAME/_NET_WM_NAME become the title, WM_DELETE_WINDOW is sent on `OKE_CLOSE`; child windows are composited by the server into the top level's buffer (clip = window rect minus later siblings minus children, `win_visible`), Expose events come from `win_expose_tree/win_expose_rect`. Fonts are fixed-cell bitmap-like fonts (`fixed`, `6x13`, XLFD names) rasterised glyph by glyph with `OKW_TEXT`; selections bridge to `OKW_CLIPBOARD` only when nobody owns them. Drawing: raster functions, plane mask, tiles/stipples, dashes, wide lines, polygons, arcs, CopyArea/CopyPlane, PutImage/GetImage, all software in `gfx.c`. Not done: passive grabs, XKB/RENDER/SHM/BIG-REQUESTS/XInput, ConfigureNotify when the desktop moves a window. **Shipping:** `tools/lx/build_root.sh` builds the product root (own programs of `lx/src`, `xokai`, our DLLs and the Windows demo exes; no host code), `make desktop`/`make disk` put it in as a GRUB `module` (`build-host/lxsys.tar`; the disk has it on p1 and, for the known-good entry, on p2); `build_tests.sh` reuses it and adds glibc/host test inputs. Test: `test_lx_image.py`. Tests: `test_lx_x11.py` (own raw-protocol client `lx/xsrv/clients/xtest.c`), `test_lx_xlib.py` (a real libX11 program `lx/test/x_xlib.c`, needs `HOSTBINS=1`). **Windows x64 programs (PE32+)** run in the same tasks: `lx_pe.c` maps the image and the DLLs it imports (search `/windows/system32`, `/windows`, `/bin`; names are case-insensitive; `api-ms-*`, kernelbase, ntdll, advapi32 resolve to our `kernel32.dll`, ucrtbase/msvcr*/api-ms-win-crt to our `msvcrt.dll`), relocates, binds imports (an unresolved one points at `0xAE000000+16*i`: a fault there names it), builds PEB/TEB/TLS in the meta region `0xAF000000` and starts through a generated stub (DllMain of every DLL, then the entry). GS base = TEB (`arch_prctl 0x1001`). Our own DLLs in `lx/win/` (kernel32 incl. the ntdll bits, msvcrt: all written from scratch, C compiled with `gcc -mabi=ms`, user mode, they use Linux system calls; services 0x1000-0x1002 = LoadLibrary/GetProcAddress/GetModuleHandle). Toolchain: `tools/pe/pebuild.sh` (gcc -> `ld -T pe.ld` -> `mkpe.py` ELF-to-PE converter, import stubs generated from `imports.txt`, exports from the `EXPORT` lines), `lx/win/build.sh` builds everything into `build-host/winroot`; `tools/pe/dump.py` lists a PE's imports. Windows rule: functions are entered with rsp = 8 mod 16 (the start stub keeps rsp 16-aligned before each call). **SEH** (`lx/win/kernel32/seh.c`, all user mode): a fault of a Windows task is not a signal: the kernel (`win_exception` in lx.c) copies the registers to the user stack and continues at `KiFaultEntry` (registered by kernel32's DllMain with arch_prctl 0x1005), which builds CONTEXT + EXCEPTION_RECORD and walks the stack with `.pdata`/`.xdata` (`RtlLookupFunctionEntry`/`RtlVirtualUnwind`, module of an address = service 0x1003), calling language handlers (`__C_specific_handler` = scope tables of __try/__except/__finally; `RtlUnwindEx` runs the termination handlers and lands in the __except block). Our own code gets unwind tables from gcc's CFI (`tools/pe/unwind.py`, run by mkpe; needs `-fasynchronous-unwind-tables -fno-shrink-wrap`, `ld -q`; `MKPE_UNWIND_VERBOSE=1` lists functions it could not describe: frame pointer / DRAP functions and noreturn ones). gcc has no `__try`, so tests write guarded regions in assembler with hand made UNWIND_INFO in `.sehdata`/`.sehfunc` (32-bit relocations there become RVAs). Not done: C++ exceptions (`__CxxFrameHandler3/4`, `_CxxThrowException`), epilogue emulation in RtlVirtualUnwind, stack overflow detection. Test: `lx/win/tests/seh` via `test_lx.py`. **GUI:** `/dev/okwin` (`src/lx_okwin.c/.h`, protocol shared with user space) is the native window device: `OKW_CREATE/MAP` give a window with a shared BGRX buffer, `OKW_PRESENT` publishes a rectangle, events (mouse, wheel, Linux key code, char, focus, close, resize) are `read()`, `OKW_TEXT` rasterises UTF-8 with the kernel's Noto engine into a coverage mask, `OKW_QUERY` = window position and pointer. Our `gdi32.dll` (`lx/win/gdi32`: DCs over pixel surfaces, pens/brushes/bitmaps/DIBs, shapes, BitBlt, text via OKW_TEXT; private `__gdi_*` exports for user32) and `user32.dll` (`lx/win/user32`: classes, window tree with child windows drawn into the top level's buffer, one message queue, WM_PAINT/timers/input translation, DefWindowProc, MessageBox, built-in BUTTON/STATIC/EDIT/LISTBOX, wsprintf) run on it; menus (bar, popups, submenus, mnemonics, `menu.c`; popups are frameless okwin windows, `OKW_F_NOFRAME`), accelerators, dialogs (`dlg.c`: both template formats, DialogBox/CreateDialog, IsDialogMessage), resources (`res.c`: bitmaps/icons/cursors from PE resources or files, LoadString in draw.c, FindResource/.mui in kernel32 `rsrc.c`), the clipboard (`clip.c`, text shared through `OKW_CLIPBOARD`), COMBOBOX (`combo.c`), SCROLLBAR controls and the scroll bars of windows (`sbar.c`: 17 px margins, client area reduced) are real. NOT done: common controls (comctl32: list/tree view, toolbar, status bar...), comdlg32, shell32, registry, winmm, ws2_32, C++ exceptions. Resources for our own test programs: a `rsrc.txt` in the program's directory (`tools/pe/rsrc.py` spec: BITMAP/ICON/MENU/DIALOG/ACCELERATOR/RCDATA/STRINGS) becomes the .rsrc section, `gen.py` there makes the binary templates. Build traps: `pebuild.sh` has `-Werror=implicit-function-declaration` (a pointer-returning function used undeclared is truncated to int: that was a real crash); `KEEP_ELF=1` keeps the linked ELF next to the dll for `nm`; the unhandled-exception message prints a call trace. Key presses and releases reach okwin through an IRQ queue (`keyboard_next_transition`), and a window created with `OKW_F_HIDDEN` is shown (with the opening animation) by `OKW_SHOW 1`. Bases: kernel32 0x6C000000, msvcrt 0x6D000000, user32 0x6E000000, gdi32 0x6F000000. A test exe with a `gui` marker file in its directory is built as GUI subsystem. Real Microsoft console binaries run (findstr.exe, sort.exe from the host's System32; test `test_lx_msbin.py`, the files are not in the repo): `lx/win/kernel32/rsrc.c` has FindResource/LoadResource on the mapped image with the fallback to `<dir>/en-US/<name>.mui` (RT_MESSAGETABLE for FormatMessage, RT_STRING for LoadString); our `FILE` is 48 bytes because compiled programs index `__iob_func()` with the MS stride. Shell `lx trace on|off` prints every Linux system call with its path argument (`[lxt]` serial lines): the first tool when a foreign binary prints nothing. Test programs: `lx/win/tests/*` (hello.exe, crtdemo.exe, guidemo.exe); GUI test `tests/headless/test_lx_win32gui.py`, device test `test_lx_okwin.py`. Trap: Python `open(p).write()` on Windows turns LF into CRLF (breaks `sh` scripts); use `newline=''`. Tests: `HOSTBINS=1 sh tools/lx/build_tests.sh` builds `build-host/lxtest.iso` (programs of `lx/src` without libc + glibc tests of `lx/test` + host bash/ls), then `tests/headless/test_lx.py`, `test_lx_gui.py`. Trap: the Bash tool collapses `\\` in commands, so write perl/C that contains backslashes with the Write tool.
- **okai on Windows** (`win32/`, `make win` → `build-host/okai.exe` stripped + `okai-debug.exe` with symbols from the same link): the same `okai.c`/`okai_ui.c` + `src/web` + `src/ojs` + `src/net` + `src/crypto` + `src/media` as a 32-bit MinGW-w64 GUI app. `win_gfx.c` (DIB backbuffer + damage), `win_window.c`, `win_sys.c` (heap names, `serial_*` → `okai.log`, 100 Hz `tick_count` thread, `smp_*` over a thread pool, entropy), `win_net.c` (`tcp_*`/`dns_lookup` over Winsock), `win_audio.c` (waveOut), `win_main.c` (WinMain + `desktop.c`'s loop and input routing). Frameless window (`WS_POPUP|WS_THICKFRAME`, `WM_NCCALCSIZE`=0): `WM_NCHITTEST` gives the tab-strip background as `HTCAPTION` (drag), resize edges in the outer 6 px, and `HTCLIENT` for every okai control; `WM_GETMINMAXINFO` clamps maximise to the work area. No taskbar band: the backbuffer is the client area and `okai_open`'s `SCREEN_H - TASKBAR_H` window is stretched by `win_window_fit_full`. `-DOKAI_PORT` is the only switch the shared sources test (CPRNG in `tls_client.c`, sound + frame budget in `wjs_media.c`, video workers in `meng.c`, parallel GC in `wjs_sys.c`); it is never defined for the kernel, which is unchanged. Traps: **32-bit only** (`rdtsc "=A"`, inline `divl`), `x509_set_now()` is mandatory or every HTTPS chain fails closed as CV_ERR_EXPIRED, the CPRNG must be seeded and stirred (BOOT + TIMER in the same pool window) at start or TLS aborts with TLS_FAIL_RNG, **no `OutputDebugString`** (raises DBG_PRINTEXCEPTION_C, which kills a GUI process with no debugger: log to a file), **never `free()` a DIB section's bits** (heap corruption on every resize; `bb_owned` in win_gfx.c guards it), `okai_open` creates its own window (a second `window_create` in WinMain left an empty slot 0 that swallowed every click), `WM_NCHITTEST`/`WM_MOUSEWHEEL` lParam are SCREEN coordinates while everything okai does is client, the wheel sign is inverted vs the kernel (Windows positive = away = up), and okai scrolls on 0x10/0x11/0x04/0x12 (map VK_DOWN/UP/NEXT/PRIOR). **A waveOut callback gets `WAVEHDR.dwUser` as its first data argument:** leaving it 0 dereferences NULL inside a *system* callback, which Windows reports as 0xC000041D + 0xC0000029 (unwind failure) rather than an AV, so the unhandled filter never runs — hence `win_audio.c` sets `dwUser = the buffer` and `win_sys.c` logs crash records through a raw `WriteFile` plus a vectored handler (`win_crash_log`). A process that dies in a callback leaves *nothing* in `okai.log` otherwise, and `Application` log WER entries give the exception code. **waveOut headers are prepared once at init and unprepared only at shutdown:** `audio_flush` (pause, seek, session teardown) does `waveOutReset` and then *waits for `WHDR_DONE`* before handing a buffer back — unpreparing or rewriting a buffer the driver still owns corrupts winmm/ntdll bookkeeping and surfaces as 0xC0000409 in ntdll (uncatchable) a minute later, on a page that was playing fine. `win32/win_heap.c` defines `malloc/free/realloc/calloc/strdup` for the whole process; `OKAI_HCHK=1` switches it to a guarded allocator (private heap, 16-byte trailing guards, live-block list, 2 Hz sweep from the main loop) that reports an overrun at its **allocation site**, resolved with `i686-w64-mingw32-addr2line -e build-host/okai-debug.exe`. Synthetic mouse input does not reach the window in a non-interactive session (so `WM_NCHITTEST` answers are asserted directly and the drag gesture is human-checked); the rest is `win32/test-gui.ps1` + `win32/test-frameless.ps1`.
- **Window chrome** (`src/winfx.c`): corners are rounded (`WIN_RADIUS` 12, not when maximized) by a pass over the four corner squares of whatever rectangle was just painted square (`winfx_round_corners`, called at the end of `window_paint_region`, after okai overlays and after a drag blit): the scene BELOW the window's z is recomposited into the square (`desktop_paint_below`), edge pixels are anti-aliased, the 2 px ring follows the arc, interior pixels are kept. It is idempotent by construction (a pixel never depends on its own previous value outside the arc): keep it that way, repainting must be able to call it any number of times. Anything that paints a window's rectangle outside `window_paint_region` must call it afterwards. Title bars show the taskbar's app icon and the title from the LEFT. Animations: a new window grows/fades in, minimize shrinks into its taskbar button, restore is the reverse (200-250 ms). While one runs `winfx_hides(id)` is true and the compositor (paint region, occlusion, overlays, vis lists) ignores the window; the animation owns a snapshot of the window (alpha 0 outside the corners) and a copy of the scene, and writes the union of previous and new rectangle every tick (`[winfx] open|minimize|restore win= frames= ms=` on serial). One animation at a time (a new one ends the running one); no memory = no animation. Closing (`winfx_close_prepare` before `window_destroy` frees anything, `winfx_close_commit` after) fades the window out from its snapshot; `winfx_hides` ignores it because the id may be reused. **Drop shadows** (`winfx_shadow`, `SH_R` 16, offset 6, peak alpha 112) darken everything below a window outside its rectangle and are part of the scene model: `desktop_paint_rect_z` casts them in z order (windows count when their shadow bounds reach the region), a lower window that repaints part of itself re-applies the shadows above it (`winfx_shadows_above`, in `window_paint_uncovered` and after okai overlays), the corner pass adds the window's own shadow under the arcs, a drag recomposites old+new shadow bounds around the blit, and raise/destroy/minimize/maximize repair `winfx_shadow_bounds`. Anything that repairs a window's old footprint must grow it (`winfx_grow_rect`). Never apply a shadow twice to unrepainted pixels. Test: `tests/headless/test_winfx.py`.
- **Image size:** `_kernel_end` must stay in the boot PD's 64M window; UEFI mbi must sit below 64 MB.

## Hardware and platform work (all on a Cherry Trail laptop; details in HANDOFF.md / `LAPTOP.md`)

- **Boot/UEFI:** `kanarchy-laptop.iso` boots BIOS and UEFI; `src/fbtext.c` draws the text-mode report on the GOP framebuffer; `memory_init` frees only type-1 map pages above the kernel; MULTIBOOT flag bit 0 = mem.
- **Power:** `src/acpi_pm.c` (FADT, `_S5_` from the DSDT, reset register, 0xCF9/KBC fallbacks). Verified in QEMU only.
- **CPU:** `src/cpufreq.c` calibrates TSC/core clock and a small benchmark → speed factor (dev PC = 1, laptop ~6-8) that scales JS time budgets, blocks muted autoplay until a click, caps codec levels and enables the media governor; shell `cpu`, `cpu slow N|auto`. **It WRITES NO power/clock MSRs** (PERF_CTL ratio without the VID froze the laptop). MSR access is fault-safe (`rdmsr_safe/wrmsr_safe`; the new EIP store in `isr_handler` must be volatile + compiler barrier).

## Web engine, JS and okai

- **Engine rules (`src/web`):** integer/fixed-point only (LU = 1/64 px), no FPU; no libgcc (64-bit `/` `%` link `__divdi3`: use `w_div64`/`w_muldiv`); every engine call from okai goes through `run_job()` (private 1 MB stack). Sources also build on the host (`tests/web/build.sh`, `make web-tests`): fix layout bugs there against Edge (`tests/web/compare.py`) then rebuild the kernel. Exception: `wcanvas.c` and `wasm.c` use doubles.
- **ojs** (`src/ojs`, our JS engine; see `src/ojs/README`): NaN-boxed values, stack bytecode VM, mark-sweep non-moving GC with conservative C-stack scan (values kept in C heap memory must be roots: `ojs_add_root[_range]`; wjs re-registers on growth). Every realm entry sets x87 to 53-bit precision; never cast double→int in hot paths (use `d2i64/d2u32/dtoi32`). Realm heap = half the kernel heap (96-512 MB), 4 s per script / 3 s per task (× CPU speed factor). Inline caches: 2-way, prototype chains, accessors, property additions, survive GC; any change to prototype/shape handling must keep `tests/ojs/ic_semantics.js` passing (also under `OJS_GCSTRESS`). Parallel GC marking for heaps ≥ 24 MB (`gcpar on|off`, `OJS_GCPAR_VERIFY=1` checks it). Gates: test262 (`tests/ojs/run262.py`, baseline fail list `build-host/t262_base_fails.txt`, 79936/79942 since 2026-10-29: the remaining failures are the TLA family (async-module evaluation that a dynamic import joins mid-flight, CycleRoot re-evaluation of an errored cycle, for-await close vs sibling blocking). The runner skips tests flagged CanBlockIsTrue (one agent: Atomics.wait throws TypeError) and anything using $262.createRealm (one realm)), corpus 11/12 vs node, smoke/ic_semantics/upvals/manyconsts.
- **Baseline JIT** (`src/ojs/jit.c`, `vm_body.c` included twice as `vm_run` and `vm_step`): ON (tiered, threshold 40 calls) by default in the kernel; OFF on the host (`OJS_JIT=1|2`, `OJS_JIT_THRESHOLD`, `OJS_JIT_STATS`, `OJS_JIT_DUMP`); shell `jit off|on|eager|N`. Values stay in the interpreter frame; stack depths are static (`jan_run`, effect table `op_fx`, checked by `-DOJS_JIT_CHECK`); anything unsupported or failing a guard runs in `vm_step`; slow paths are C helpers `jit_h_*` (exception answer 0 → unwinder); code lives in dedicated 256 KB whole-page pools (QEMU TCG invalidates translations of written pages). Every JIT change must keep the failing set of test262 identical with `OJS_JIT=2` and `OJS_JIT=1 OJS_JIT_THRESHOLD=2`, and kernel tests under `OKVM_PRECMD="jit eager"` (run them one at a time). The JIT does not speed up YouTube page load (style/layout dominate); it speeds up pure JS loops 1.5-3x.
- **Web APIs:** prefer plain JS in `src/web/wjs_prelude.js`; add a C native in `wjs_dom.c` (on the `W` object) only if it needs engine internals. Done in the prelude/natives: DOM + MutationObserver/ResizeObserver/IntersectionObserver, fetch/XHR (streaming bodies, Range, POST; XHR streams too: readyState 3 + `progress` per piece, growing `responseText`, `overrideMimeType` incl. x-user-defined, and `abort()`/timeout call `W.fetchCancel` → okai `fetch_end`s the transfer - video.js sniffs a container from the first bytes of a whole-file GET and aborts it), DOMParser XML documents (`parseXML`: names keep their case, elements of other namespaces are `NS_XML`), Blob/File/FileReader, streams, crypto.subtle (not constant time), Workers (run in the page realm in a sandbox), MessageChannel, window.postMessage between iframes (`RemoteWindow`), IndexedDB/Cache (in memory), canvas 2D (`wcanvas.c`), WebAssembly (`wasm.c`, MVP + 2.0 subset), HTMLMediaElement/MediaSource. Missing: WebGL, WebAudio, WebRTC, EME, WebCodecs, ServiceWorker, Trusted Types, `Intl`, `navigator.userAgentData`. `navigator`/`screen`/`performance` follow WebIDL shape (getters on prototypes). `offsetParent` is CSSOM (null for body/html/fixed; positioned ancestor otherwise; offsetTop/Left relative to it): a constant `<body>` made `while (el.offsetParent)` loops spin until the script budget killed them. `SourceBufferList` has real indexed properties (players test `Array.prototype.indexOf.call(ms.sourceBuffers, sb)`). `tests/web/js/surface.js` + `edge_surface.txt` diff the API surface against Edge. Tests: `make web-tests`, `tests/web/test_webapi.sh`, `tests/web/js/*.html` (`basic.html` must stay ALLPASS).
- **Paint/layout:** layout memoises BFC subtrees (`lay_box`, disable with `WB_NOMEMO=1` for A/B); hit testing follows paint order (`wlay_paint_rank`); the painter repaints only damaged item rectangles (`wpaint_inc`; anything that clears/edits a surface behind the painter must call `wdoc_paint_invalidate`; shell `damage on|off|check`); style/layout/paint loops call `W_PROGRESS()` to service media. Style (`css_compute_all`) is the dominant page-load cost; the rule index files rules under key tags. Stylesheets are shared by content hash (`d->sc[]`).
- **okai** (`okai.c`, chrome in `okai_ui.c`): tabs, request table (`struct oreq`; finished requests are DETACHED before delivery because delivery can navigate), preload scanner (`pscan.c`) + preview of large documents, lazy images, iframes as tab slots ≥ `OKAI_MAX_TABS` (own ARGB bitmap, routed input), forms incl. POST (no multipart), `<label>` forwarding. `ui_layout()` is the only chrome geometry source (draw and hit tests share it); per-frame state must be in `state_sig()`. Damage repairs never re-render cached chrome. URLs up to 8192 bytes, cookies up to ~9.8 KB. There is deliberately no search feature in the address bar.
- **Adblocker (`src/ablock.c/.h`, always on, no toggle).** Lists = `filters/easylist.txt` + `easyprivacy.txt` (third-party *data*, CC-BY, see `filters/LICENSE-NOTE.md`) shipped as the second GRUB `module` with cmdline tag `ablock` (`build-host/ablists.txt`; the ISO recipe, `tools/disk/grub.cfg` and `mkdisk.py` carry it; a missing module = empty engine, fail open). Parsed in idle-path slices (`ablock_parse_step` next to `heap_pretouch`); the first check drains the rest synchronously. **Network:** the check sits at the top of `req_fetch` (okai.c) and returns -3 — before the cache, the prefetch and `fetch_begin`, so every page request is filtered: documents, frames, subresources, preload, XHR/fetch, media Range GETs and redirects (DoH and `mplay` use `fetch_begin` directly and are never filtered). Semantics: `||host^` rules live in a record-backed host hash set (parent domains checked, `$badfilter` can kill them); the rest in token buckets (uBlock's anchor-token scheme; tokens adjacent to `*` are excluded so a match implies the token is a URL run); verdict order `$important` > `@@` exceptions > blocks; untyped filters never match a top-level document; regex `/…/` filters are matched as their literal inner text; anything unsupported (`redirect=`, `csp=`, `removeparam=`, `$popup`, procedural cosmetics, …) drops the line and is counted in the `[ablk]` load summary. **Cosmetic:** hide rules are name-hash indexed at parse; per document `ablock_doc_css` emits only what the DOM actually uses (CSS atoms are per-document, so one big shared sheet can NOT be reused across documents) into a small stylesheet added last with `!important` (`ablock_sheet_add` in wdoc.c, re-attached by `rebuild_styles`); script mutations (`wjs_inserted`/`wjs_attr_changed`) set a dirty flag that `wdoc_update` re-collects (200 ms throttle). Blocked requests surface as natural failures (img error events, fetch() rejection, error page for documents). **Scriptlets** (`##+js(name, args...)`, aliases `set`/`acs`/`rmnt`/`aost`/`aeld`): our own JS library (`SCLIB` in ablock.c, written from the documented semantics — nothing copied), generated per document by `ablock_doc_scriptlets` and injected into the page realm BEFORE any page script (`wjs_inject_scriptlets`, called from wdoc.c right after wjs_new, evaluated with OJS_EVAL_HIDE_SOURCE). Implemented: set-constant, abort-current-inline-script (document.currentScript + needle), abort-on-property-write, abort-on-addEventListener, remove-node-text, set-cookie, set-local-storage-item, cookie-remover, no-fetch-if, no-xhr-if; json-edit/trusted-* stay no-ops. **`$redirect=`**: built-in resources (noopjs, nooptext/noop.txt, noopjson, 1x1.gif; any other `*.js` name maps to noopjs) are served in `req_fetch` through the same JOB_FETCH_DONE job the data:-URL path uses (req_fetch returns -4; subresources only, documents never). **`:has-text(needle)`** (the one procedural form the lists use; must be trailing, needle not a regex): the base selector is verified per element with css_selq, the element's text searched, the element tagged `data-ablk-h="r<N>"` and `[data-ablk-h="rN"]{display:none!important}` emitted — every cosmetic rule is name-keyed now, host rules only apply after the host scan marked them. Still skipped+counted: `$popup` (okai has no window.open), regex needles, `csp=`/`removeparam=`/`uritransform=`/`permissions=`, `method=`/`dns*`, `-abp-properties`. Log tag `[ablk]`: load summary, one line per block/redirect, per-page hide bytes. Tests: `tests/test_ablock.c` (`make host-tests`), `tests/headless/test_ablock.py` (build with `make desktop ABLOCK_EXTRA=tests/headless/ablock_test.txt`, run with `OKVM_ISO=kanarchy-desktop.iso`; switching ABLOCK_EXTRA needs `rm build-host/ablists.txt` — the variable is not a make dependency).
- **Networking:** polled e1000 (256 RX descriptors) or Wi-Fi shim; TCP socket table (16 sockets, 256 KB receive rings, window scaling, SACK, 64 OOO slots; fast-retransmit counts pure ACKs only; the advertised window is the ring's free space); DNS over HTTPS first (cloudflare, google, quad9) then UDP (shell `doh`); `src/net/fetch.c` = up to 16 parallel GETs over a keep-alive pool (`CONN_MAX` 12, 6 per host), HTTP/2 (`h2.c`, `hpack.c`; one session per origin), recent-failure list (`neg_*`), in-memory cache (`fcache.c`). Per-second `[net]` line shows rx/tx/loss/unread. Per-packet logs behind shell `nettrace`.
- **TLS** (`src/crypto/`): TLS 1.3 only (ChaCha20-Poly1305, AES-128-GCM), X.509 chain verification anchored on Mozilla's roots generated from NSS `certdata.txt` by `tools/gen_roots.py` (never regenerate from the Debian PEM bundle: it loses distrust-after dates), name-bound `root_issued()`, OCSP staples (only REVOKED / Must-Staple hard-fail), signature memo, Shamir ECDSA verify. Suites: `make host-tests`, `make host-tests-asan` after crypto/TLS changes; `tls_scan` over `tests/tls_hosts.txt`.

## Media (own decoders, all written from the standards)

- **Codecs:** Opus CELT (all channel layouts incl. multistream/5.1 downmix; SILK/hybrid frames decode as SILENCE), VP9 (bit-exact on 23 ffmpeg vectors; SSE2 MC and loop filter; tile-parallel decode and a loop-filter wavefront), H.264 Baseline/Main/High progressive 8-bit (CAVLC+CABAC; interlaced/10-bit unsupported), AAC-LC (no SBR/LTP/Main), WebM and MP4 demuxers (incremental, fragmented MP4 ok), polyphase resampler to 48 kHz. Test vectors are made with a host ffmpeg (`tests/media/gen_*_vectors.py`, git-ignored `tests/media/vec/`); the RFC 6716 reference decoder in WSL (`~/opus_oracle`) is the Opus oracle. Run `make media-tests`, `sh tests/media/build_meng.sh`, `build_h264.sh`, `build_aac.sh`.
- **`meng`** (`src/media/meng.c`) is the playback core under `play <url>` and `<video>/<audio>`/MediaSource: source buffers → packet queues ordered by DTS → audio decoded ~0.5 s ahead into the card → video decoded on a worker CPU (`vw_*` ring, convert jobs in `vcvt.c`) → newest due frame copied to the page. Media clock = audio clock (rebased after underruns); with no sound card a 100 Hz tick drives it. The clock is HELD (stalled at the requested position) until tracks are known and ≥ 0.3 s is buffered (`clock_start_or_hold`; test `test_play_before_data`). One session owns the sound card (`WM_MAX` 6). `timestampOffset`, `appendWindow`, `changeType` are supported; mixed codecs in one queue are not. A new H.264 init segment on a running stream (a player's quality switch) does NOT replace the decoder: its SPS/PPS are prepended in band to the next video sample (`sb_set_inband`), so queued frames of the old level still decode with their references (test `test_mp4_requality`). Ranged requests never use the response cache (`has_range_header` in fetch.c).
- **Web side:** `src/web/wjs_media.c` + prelude (`mimeKinds`, `levelCap`, `mediaStream`: plain `<video src>` is read with 2 MB Range pieces, 45 s read-ahead; seeking past the buffered part, MP4 with moov at the end, and MP4/WebM with an audio track on a machine with NO sound card do not work). Natives are driven from the main loop (`media_pump`, `wjs_media_poll`), also from the 20 ms script hook. Shell: `vidfps` (corner overlay + `[vidfps]` serial line: dec/scr/drop/gap/buf), `vp9par`, `progress`, `play`. `[media] rate:` once a second while playing.
- **YouTube:** watch pages load and play (VP9 + Opus through MSE, SABR over POST) at 28-31 fps with ~0 dropped under WHPX. **Open issue — playback is cut after ~25-60 s:** the video servers answer SABR requests with a 107/123-byte message (UMP parts PLAYBACK_START_POLICY + STREAM_PROTECTION_STATUS = ATTESTATION_REQUIRED) and `youtubei/v1/player` returns `400 FAILED_PRECONDITION`, although the page's own BotGuard run completes and GenerateIT returns an integrity token. Signed-in did not change it. What was measured (API-trace diffs against Edge; BotGuard computes its signals inside its own VM from JS-engine behaviour, so an API trace cannot show them; the tracer tools were removed on 2026-10-20 with the rest of the investigation and can be recovered from commit `a56957e`) is in git history; known remaining differences from a real Chrome: no Trusted Types, no `Intl`, no WebGL/WebAudio, stub `about:blank` iframe realms, a different JS engine. Not a decided direction: whether and how to address this is the owner's call, not a settled project rule. From EU exit IPs a cookie-consent lightbox pauses the video until the user clicks it (`perf_win.ps1 -ClickAt "932,857@16"` in tests).
- **Invidious** (e.g. `https://inv.nadeko.net/watch?v=...`): plays in okai since 2026-10-22 (video.js 7 + VHS, DASH H.264 + AAC through the instance's companion proxy, 144p-720p ABR switches; plays a video to the end under WHPX). ## Architecture in 30 seconds

1. GRUB loads the kernel at 1 MB with multiboot info (memory map + framebuffer).
2. `start.asm` LOW `_start` builds the boot PD → `_start_high` → `kernel_main()`.
3. `kernel_main()`: GDT → IDT → memory → paging → process table → graphics → windows → mouse → keyboard → USB/I2C/Wi-Fi/audio → networking → `sti` → main loop.
4. Main loop: keys → mouse → `okai_poll()` (fetches, sub-resources, coalesced renders) → JS timers/media → windows → flush dirty rows; sleeps when idle.
5. Scripts, stylesheets and images are fetched in parallel after the document parses; scripts run in the document's ojs realm under time budgets.

## Adding features

- **Shell command:** `shell_execute()` in `desktop.c` (desktop) or `shell.c` (text), `str_eq(cmd_buf, "name")` pattern.
- **Window:** `window_create()`, `window_puts()`, `window_set_close_button()`.
- **Interrupt handler:** stub in `isr.asm` (`ISR_NOERRCODE`/`ISR_ERRCODE`), register in `idt_init()`.
- **Drawing primitive:** `graphics.c`, write to `backbuffer[]`, mark dirty.
- **Web API:** see "Web APIs" above; test on the host first.
- **Process feature:** `process.c/.h`, new fields at the tail.

## Text vs desktop

Separate binaries from different source sets. Text: `kernel.c vga.c terminal.c shell.c`. Desktop: `desktop.c graphics.c window.c paging.c filesystem.c editor.c textslot.c okai.c web/* ojs/* net/* crypto/* media/* ...`. Shared: `gdt.c idt.c memory.c serial.c keyboard.c mouse.c io.h`. Test both builds when touching shared code. Networking, TLS, web engine, ojs, okai and media are desktop-only.

## Headless testing (okvm)

`tests/headless/okvm.py` drives QEMU headlessly; output in `~/okvm/`. Docs: `tests/headless/TESTING.md`; parallel runner `python3 tests/headless/run_suite.py -j3 test_*.py`.

```python
import sys, time; sys.path.insert(0, 'tests/headless')
from okvm import OkVM
vm = OkVM("tag")
vm.wait_for("[mem] heap", timeout=40); time.sleep(10)
vm.type_string("okai\n"); vm.wait_for("home rendered", timeout=30)

vm.kill()
```

- Run after touching window/mouse/keyboard code: `test_nav.py`, `test_okai_interact.py`, `test_desktop_ui.py`, `test_typing.py`, `test_boot_keys.py`. Hover/repaint races only show with real-mouse timing: `powershell -File tests\headless\hover_win.ps1` (WHPX). Other end-to-end tests: `test_okai_js.py`, `test_okai_page.py`, `test_sites.py` (a plain-HTTP fallback counts as failure), `test_okai_media.py` (timing-marginal under TCG; runs with `OKVM_SMP=2`), `test_okai_frames.py`, `test_okai_postmessage.py`, `test_okai_stream.py`, `test_okai_wasm.py`.
- Env knobs: `OKVM_ACCEL=kvm`, `OKVM_ISO=path` (test another build), `OKVM_PRECMD=...`, `OKVM_VGA=virtio`, `OKVM_SMP`, `OKVM_CPU`, `OKVM_TRACE='ps2_*'`, `OKVM_PCAP=1`.
- Under TCG QEMU sometimes stops running the guest for 0.2-0.6 s, and its PS/2 queue holds 8 keys: an occasional garbled typed word in `test_sites` with `lost>0` in the PS/2 trace is QEMU, not the kernel.
- Stale QEMU processes from an aborted run keep an okvm tag's serial log and make the next run hang: run kernel tests one at a time and `pkill -f "[q]emu-system"` (bracket form; the plain pattern kills the invoking shell).

## Working-environment traps

- WSL from Git Bash: `/tmp` differs between them; use `MSYS_NO_PATHCONV=1 wsl -e ...` and keep scripts inside the repo (`/mnt/d/...`). `sed -i` across drives fails (write to a temp file). Node runs on Windows only. A WSL `git stash pop` shows spurious CRLF "modified" files: check with Windows git. Once 418 files showed mode `----------` in WSL: `find . -path ./.git -prune -o -type f -perm 000 -print0 | xargs -0 chmod 755`.
- Python patch scripts put real newlines into C string literals when the source contains `\n`: make such edits with the Edit tool. Windows filenames cannot contain `<>`.
- Host servers used by tests: WSL `python3 -m http.server 8005`, slow server 8006, filesrv 8010.
